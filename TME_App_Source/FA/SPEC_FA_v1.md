# TME Хөрөнгийн тооллого (FA) — дизайн v1

Тусдаа canvas апп. Үндсэн тооллогын аппын цэснээс `Launch()`-аар нээгдэнэ.
**Хэмжээ:** 10,000+ үндсэн хөрөнгө, шошготой (баркод/QR). Шошгогүй бол дугаар/нэрээр хайна. **Тоологч:** 2 хөрөнгийн нягтлан. Хэрэглэгчийн хэлснээр анхны бэлтгэл (SharePoint `AssetCounts`, BC холболт) хийгдсэн. Дизайн хийгдээгүй байсан.

## 0. Зарчим
1. **Зөв байдал → аюулгүй байдал → хурд**, офлайн ажиллана (барааны тооллоготой ижил).
2. Нэг хөрөнгө нэг сесст **нэг эцсийн үр дүнтэй**. Дахин уншуулбал анхааруулна. Шинэчилбэл хамгийн сүүлийнх нь хүчинтэй, өмнөх нь аудитад үлдэнэ.
3. Төхөөрөмж зөвхөн **илгээгээгүй мөрөө** хадгалалт бүрт дискэнд бичнэ (r5-ийн арга). 10,000 хөрөнгө тоолоход ч хурд буурахгүй.
4. "Олдоогүй" жагсаалтыг **сервер (flow)** гаргана. 10,000 × 10,000-ийн тулгалтыг утсан дээр хийхгүй.
5. MVP-д BC-д **автоматаар бичихгүй**. Нягтлан тайлангаар шалгаж оруулна.

## 1. Өгөгдөл
### BC (эх сурвалж, зөвхөн уншина)
| API | Талбар |
|---|---|
| `fixedAssets (v2.0)` | `number`, `displayName`, `serialNumber`, `fixedAssetLocationCode`, `employeeNumber`, `classCode`, `subclassCode`, `blocked`, `underMaintenance` |
| `fixedAssetLocations (v2.0)` | `code`, `displayName` |
| `employees (v2.0)` | `number`, `displayName` (хариуцагчийн нэр) |

Аппаас BC-ийг шууд уншвал 5,000 мөрийн хязгаарт тулж **дутуу ирнэ**. Тиймээс §3-ын snapshot flow-оор уншина.

### SharePoint (TME_Finance)
**`AssetCounts`** (байгаа). Бүх талбар нь Text, `CountedAt` нь DateTime.
| Талбар | Утга |
|---|---|
| `ClientRequestId` | Төхөөрөмж үүсгэсэн GUID. **Enforce unique + index.** Давтан илгээхэд давхардуулахгүй |
| `SessionId` | idx |
| `AssetNo` | idx. Бүртгэлгүй хөрөнгө бол `NEW-<6 тэмдэгт>` |
| `AssetName`, `ExpectedLocation`, `ExpectedResponsible` | Скан хийх үеийн snapshot-оос |
| `ObservedLocation`, `ObservedResponsible` | Нягтлан бодитоор харсан |
| `CountStatus` | idx. `Found` / `WrongLocation` / `WrongResponsible` / `WrongBoth` / `Damaged` / `Unregistered` / `Superseded` |
| `CountedAt` | Төхөөрөмжийн цаг |
| `Notes` | Тайлбар, эвдрэлийн тодорхойлолт |
| `CompanyCode` | `TME` |
| `Title` | `AssetNo` (жагсаалтаас харахад хялбар) |

Нэмэх багана: `ConditionCode` (Text: `OK`/`Damaged`/`Repair`/`Idle`), `PhotoUrl` (Text), `DeviceId` (Text), `CounterEmail` (Text, idx).
⚠️ Index-ийг **жагсаалт хоосон байхад одоо** нэмнэ: `ClientRequestId`(unique), `SessionId`, `AssetNo`, `CountStatus`, `CounterEmail`. Нэг тооллого 10,000+ мөр үүсгэнэ.

**`AssetCountSessions`** (шинэ, жижиг)
| Талбар | Утга |
|---|---|
| `Title` | `SessionId` (unique), жишээ `FA-2026-12` |
| `SessionName`, `LocationScope` (`|L1|L2|` эсвэл `*`) | |
| `Status` | `Open` / `Closed` |
| `SnapshotAsOf`, `OpenedAt`, `ClosedAt`, `OpenedBy` | |
| `ReportUrl` | Хаах үед flow бичнэ |

**`AssetPhotos`** (document library, сонголттой). Зургийг flow хадгалж, `PhotoUrl`-д холбоосыг бичнэ.

### Эрх (`AssetUserAccess`, байгаа хүснэгт)
- `|fa|` — тоолох, `|faadmin|` — сесс нээх/хаах, тайлан. `LocationCode` нь `*` эсвэл `|L1|L2|`.
- Админы имэйлийг кодонд шууд бичихгүй.

## 2. Төхөөрөмж дээр
| Нэр | Хадгалалт | Агуулга |
|---|---|---|
| `colFA` | `SaveData("FA_Assets_"&oid)`, зөвхөн синк хийх үед | Snapshot (~10,000 мөр) + `Counted` (Boolean) багана |
| `colFALoc`, `colFAEmp` | Синк хийх үед | Байршил, ажилтан |
| `colFAPending` | `SaveData("FA_Pending_"&oid)` **скан бүрт** (ихэвчлэн 0–30 мөр) | Илгээгээгүй үр дүн |
| `colFADone` | Санах ойд + 10 минутад нэг удаа диск | Энэ сесст тоологдсон дугаарууд (өөрийн болон серверээс) |
| `varFASession`, `varFARoom`, `varFADeviceId` | `SaveData` | Сесс, одоо байгаа өрөө/байршил, төхөөрөмж |

**Хурдны дүрэм:** `Text`/`Items` property-д 10,000 мөрийг шүүхгүй. Хайлт нь `DelayOutput`, `StartsWith`, `FirstN(…,50)`-тай. Шошгоор хайхдаа `LookUp(colFA, number=код)` ашиглана. Progress-ийг тоолуураар (`varFADoneCount`) хөтөлнө.

## 3. Flow-ууд (стандарт connector)
| Flow | Үүрэг | Буцаах |
|---|---|---|
| `FA_GetSnapshot` | Хэрэглэгч = trigger header-ийн имэйл. Эрх шалгана. BC `fixedAssets` (pagination асаалттай) + байршил + ажилтан. Эрхийн хүрээгээр шүүнэ. | `{ok, code, rowCount, asOf, assetsjson, locationsjson, employeesjson}` |
| `FA_GetSessionDone` | Тухайн сессийн `AssetCounts`-ыг pagination-тайгаар уншина (`Superseded`-ээс бусад) | `{rowCount, done:["FA001",…], byStatus:{…}}`. Нөгөө нягтлангийн тоолсныг харуулахад |
| `FA_SessionReport` | Хаах үед: snapshot − тоологдсон = **Олдоогүй**. Тулгалтыг JSON map-аар хийнэ (давталтгүй, 10,000 мөрт ч нэг action). Үр дүнг Excel хэлбэрээр `AssetPhotos`/тайлангийн санд хадгална. | `{found, wrongLocation, wrongResponsible, damaged, unregistered, notFound, reportUrl}` |
| `FA_SavePhoto` (сонголттой) | base64 зураг → library | `photoUrl` |

Тоолсон мөрүүдийг апп `AssetCounts` руу **шууд** `Patch` хийнэ (2 итгэмжлэгдсэн хэрэглэгч). Давхардлаас `ClientRequestId` (unique) болон илгээхийн өмнөх `LookUp` хамгаална. Барааны тооллогын idempotent upload загвартай ижил.

## 4. Дэлгэцүүд
**4.1 Нүүр (FA Home)**
- Нээлттэй сесс: нэр, хамрах хүрээ, `asOf`.
- Явц: `Тоологдсон N / 10,234` (миний + нөгөө нягтлангийн), илгээгээгүй `K`.
- Товч: **Скан эхлүүлэх** · Миний өнөөдрийн · Тайлан (`|faadmin|`) · Синк.
- Анхааруулга: snapshot 24 цагаас хуучин, эсвэл илгээгээгүй мөр байгаа.

**4.2 Скан** (гол дэлгэц, нэг гараар ашиглахаар)
- Дээд хэсэгт **"Одоо: <өрөө/байршил>"** (`varFARoom`) байна. Өрөө солих нь нэг товшилт.
- Камер/USB уншигч эсвэл хайлтын талбар (дугаар, серийн дугаар, нэр).
- **Хөрөнгийн карт:** нэр, дугаар, серийн дугаар, ангилал. Бүртгэлтэй байршил ба хариуцагч, BC-ийн төлөв (`blocked`, `underMaintenance`).
- Аль хэдийн тоологдсон бол шар тууз: "11/20 14:02-т Б.Нягтлан **Found** гэж тоолсон". Сонголт: *Үлдээх* / *Шинэчлэх*.
- **Автомат ангилал:**
  - Бүртгэлтэй байршил = одоогийн өрөө, хариуцагч зөрөөгүй → `Found`. **"Авто" горимд** хадгалах товч дарахгүйгээр шууд дараагийн скан руу шилжинэ.
  - Байршил зөрсөн → `WrongLocation` (ажиглагдсан байршил = одоогийн өрөө).
- Товчнууд: ✅ **Зөв** · 📍 **Өөр байршил** · 👤 **Өөр хариуцагч** (ажилтан сонгох) · ⚠️ **Эвдэрсэн/засвартай** · 📝 Тайлбар · 📷 Зураг.
- Хадгалах: `Collect(colFAPending)` → `SaveData` → дараагийн скан. Cloud-ыг хүлээхгүй.

**4.3 Бүртгэлгүй хөрөнгө**
- Шошго олдсонгүй эсвэл BC-д байхгүй бол: нэр, тайлбар, ангилал, өрөө, зураг.
- `AssetNo = NEW-xxxxxx`, `CountStatus = Unregistered`.

**4.4 Миний өнөөдрийн**
- Сүүлийн 200 скан, илгээгдсэн эсэхийн тэмдэгтэй.
- Засах нь шинэ мөр үүсгэнэ, өмнөхийг `Superseded` болгоно.

**4.5 Тайлан** (`|faadmin|`)
- Сесс хаах товч: эхлээд бүх төхөөрөмжийн илгээгээгүй мөр 0 эсэхийг шалгана, дараа нь `FA_SessionReport`.
- Төлөв тус бүрийн тоо, жагсаалт (Олдоогүй / Байршил зөрсөн / Хариуцагч зөрсөн / Эвдэрсэн / Бүртгэлгүй), Excel татах.

Дизайн нь TME-ийн өнгө (#EF5E1C, #1F2023, #F3F1EE), том товч, 4.5:1-ээс дээш ялгарал.

## 5. Давхардал ба зөрчлийн дүрэм
| Тохиолдол | Дүрэм |
|---|---|
| Нэг төхөөрөмжөөс давтан илгээх | `ClientRequestId` ижил → шинэ мөр үүсэхгүй |
| Хоёр нягтлан нэг хөрөнгө | Хоёулаа хадгалагдана. Тайланд **хамгийн сүүлийн** (`CountedAt`) үр дүн гарна. Хоёр үр дүн зөрвөл "Зөрчилтэй" гэж тусад нь тэмдэглэнэ |
| Шинэчлэх | Шинэ мөр нэмэгдэж, өмнөх мөрийг `Superseded` болгоно |
| Хаагдсан сесс | Скан хийхийг хаана. Офлайнаар хаагдсаны дараа ирсэн мөрийг хадгалж, тайланд "хожуу ирсэн" гэж тусад нь харуулна |

## 7. Үе шат
- **FA-1 (MVP):** `FA_GetSnapshot`, Нүүр, Скан (авто ангилал, зураггүй), офлайн дараалал, `AssetCounts` руу upload, Миний өнөөдрийн.
- **FA-2:** `FA_GetSessionDone` (хоёр нягтлангийн явц), Тайлан + `FA_SessionReport`, сесс нээх/хаах, Бүртгэлгүй хөрөнгө.
- **FA-3:** Зураг, BC руу бичих (байршил/хариуцагчийн өөрчлөлт: батлагдсан мөрөөр, flow-оор), шошго хэвлэх.
