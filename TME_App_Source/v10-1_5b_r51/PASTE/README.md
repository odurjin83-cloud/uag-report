# v10-1_5b r5.1 — "хадгаллаа" гэсэн тооллого алдагдахгүй төхөөрөмжийн сан

**Суурь:** `TME-v10-1_5b-r4.2-count-TEST.msapp` (Version 3, `../../v10-1_5b_r42count_studio/Src`). 15 property. Скрипт `../fix_r51.py`.
r5-ийг (`../../v10-1_5b_r5`) **орлоно** — r5-ийн тест хийсэн төхөөрөмжийн `C22P` файлыг r5.1 уншиж шилжүүлнэ.
Аудит (Copilot, OpenClaw) болон тусгаарласан Power Fx туршилтын олдвор дээр үндэслэв. Studio/Samsung дээр **туршаагүй**.

## Юу хийдэг вэ
| Хэсэг | r4.2 | r5.1 |
|---|---|---|
| Илгээгээгүй мөр (P) | Бүх түүхтэй нэг файл `C21`, нэг `JSON()` → ~1,767 мөрөөс дээш унана | Зөвхөн илгээгээгүй мөр, **хоёр ээлжит файл** `C22PA`/`C22PB` + дугаар (`Seq`). Бичилт үргэлж **шинэ хуулбарыг агуулаагүй** файл руу явна; дугаар зөвхөн `SaveData` амжилттай болсны дараа өснө |
| Ачаалах | `C21` | A, B (болон r5-ийн `C22P`)-аас **хүчинтэй, хамгийн их дугаартайг** сонгоно. Бичилт дундаа тасарсан файл хүчингүй тул өмнөх бүтэн хуулбар ачаалагдана. Файл байгаа ч **уншиж чадаагүй** бол сан "аюултай" → офлайн хадгалалт хаагдана (юу ч дарж бичихгүй) |
| Илгээсэн түүх (H) | — | `C22H`: сүүлийн 1,000 → 400 → 100 → 0 мөр (`JSON()` хязгаар). Зөвхөн түүх; илгээгээгүй мөрийг хэзээ ч тайрахгүй. Бүтэлгүйтвэл P-д нөлөөлөхгүй (тусдаа `IfError`) |
| Payload шалгалт | Алдаатай JSON-ий дараа ч `SaveData` ажиллаж болзошгүй | JSON-ийг эхлээд бүрдүүлж `IsError`, `[`…`]` шалгана; `SaveData`-ийн алдааг `IsError`-оор барина. Буруу бол дарж бичихгүй, "хадгалсангүй" харуулж, оруулсан утга хэвээр (r4.2-ийн одоогийн зан төлөв) |
| Хуучин `C21` | — | Байсаар байх үед апп нээх бүрд **SyncKey-ээр нэгтгэнэ** (анхны шилжүүлэлт ба шилжүүлэлтийн дунд апп хаагдсан тохиолдол). Шинэ P **үргэлж ялна**; ижил SyncKey-тэй боловч бараа/агуулах/тоо өөр мөр = **зөрчил** → юу ч дарахгүй, `C21` үлдэж, анхааруулга гарна |
| `C21` устгах | — | P (тухайн дугаартай файл) ба H-г **буцааж уншаад** `SyncKey + ItemNo + LocationCode + CountQty + CountDate(секунд)`-ээр мөр бүрийг тулгаж, SyncKey давхардалгүй, тоо таарсан үед л |
| Илгээгээгүй мөрийн хязгаар | Байхгүй | **800**-аас анхааруулга, **1,200**-д шинэ тооллогыг синк хийтэл хаана (P ≈ 0.7 MB-аас доош) |
| Санах ой / сэргээлт | Бүх түүх, SharePoint-оос 5,000 хүртэл | Илгээгээгүй бүх мөр + өнөөдөр+2 хоногийн илгээсэн мөр; SharePoint-оос мөн 3 хоног |

Экспорт (Dashboard/Тайлан/Аудит CSV) аль хэдийн `IfError(PA_ExportInventoryCSV.Run(JSON(...)),…)` дотор байна — `JSON()` унавал flow дуудагдахгүй. Хэсэгчилсэн файлыг бүрэн гэж илгээхгүй байх, мөр/₮-ийн тулгалт → r5.2.

## Хязгаар (MVP)
- Төхөөрөмж дээрх түүх, график, хувийн тайлан 3 хоногийг харуулна (нэгдсэн тайлан SharePoint-оос бүрэн).
- Bin/тавиурын талбар InventoryCount-д байхгүй тул тулгалтын түлхүүрт ороогүй.
- Microsoft мобайл тоглуулагчид `SaveData`-ийн тогтсон хэмжээ заагаагүй; Windows-ийн `JSON()` босгыг Samsung-ийн хязгаар гэж үзэхгүй — хамгаалалт аль ч хязгаарт ажиллана.
- `SaveData` бичилт дундаа тасрах үед файл юу болохыг Microsoft баримтжуулаагүй → хоёр ээлжит хуулбарын шалтгаан; Samsung дээр шалгана (T4).

## Урьдчилсан нөхцөл
InventoryCount-д index: `Created`, `Counter`, `CountKeyV27`, `Title`, `LocationCode`.

## Samsung P0 тест — **туршилтын бүртгэл/өгөгдлөөр**, няравын цорын ганц бодит кэш дээр биш
