# v10-1_5b r5.1 (rev 2) — "хадгаллаа" гэсэн тооллого алдагдахгүй төхөөрөмжийн сан

**Суурь:** `TME-v10-1_5b-r4.2-count-TEST.msapp` (Version 3, `../../v10-1_5b_r42count_studio/Src`). 15 property. Скрипт `../fix_r51.py`.
r5-ийг орлоно. Rev 2 нь OpenClaw ба Copilot-ийн rev 1 дээрх статик шалгалтын P0-уудыг засна. **Studio/Samsung дээр туршаагүй.**

## Зарчим
1. Илгээгээгүй мөр **гурван ээлжит файлд** (`C22PA/B/C` + `Seq`). Бичилт нь хамгийн шинэ хуулбар ч биш, "муу" ч биш хамгийн хуучин файл руу явна. `Seq` зөвхөн `SaveData` амжилттай болсны дараа өснө. Бүтэлгүйтсэн файлыг "муу" гэж тэмдэглэнэ. Бичих файл үлдээгүй бол бичилтийг татгалзана (хуучин хуулбар хэвээр).
2. **Уншигдаагүй файлыг хэзээ ч дарж бичихгүй, устгахгүй.** `LoadData` нэг удаа дахин оролдоно.
3. Апп нээгдэхэд **бүх уншигдах эх сурвалжийг** (A/B/C, r5-ийн `C22P`, `C22H`, хуучин `C21`) **SyncKey-ээр нэгтгэнэ**: хамгийн их `Revision` → илгээгдсэн (`Synced`) → шинэ эх сурвалж. Ижил SyncKey, ижил Revision боловч бараа/агуулах/тоо/огноо/эзэмшигч өөр бол **зөрчил**: юу ч дарахгүй, эх файлуудыг үлдээж анхааруулна.
4. Хадгалалт **зөвхөн** P файл байгаа ч нэг нь ч хүчингүй үед хаагдана. Нэг файл эвдэрсэн бол бусдаас сэргээж, хадгалалт **нээлттэй** (анхааруулгатай).
5. Өөр хэрэглэгчийн мөр олдвол: шүүж хаяхгүй, түүний нэрээр хадгалахгүй — хадгалалтыг зогсоож, файлуудыг үлдээнэ.
6. Илгээсэн түүх (`C22H`): 1,000 → 400 → 100 мөр. 100 ч багтахгүй бол **бичихгүй** (хуучин түүх хэвээр). Илгээгээгүй мөрийг хэзээ ч тайрахгүй.
7. Хуучин `C21` ба r5-ийн `C22P`-г устгах: P ба H-г бичиж, **буцааж уншиж**, `SyncKey + ItemNo + LocationCode + CountQty + CountDate(секунд) + OwnerEmail`-ээр мөр бүрийг хоёр чиглэлд тулгаж таарсны дараа — **бөгөөд** `varCountMigrateDeleteV22=true` үед л. **TEST-д `false`** (App.OnStart): шалгагдсан ч устгахгүй, тест бүтэлгүйтсэн ч тулгах эх өгөгдөл үлдэнэ.
8. Илгээгээгүй мөр (бүх эзэмшигч): 800-аас анхааруулга, 1,200-д шинэ тооллогыг синк хийтэл хаана. Шинэ тооллого үүсгэдэг цорын ганц газар нь `scrWarehouses.Button1_2` (кодоор шалгасан).
9. Санах ой: илгээгээгүй бүх мөр + `varCountWindowStartV22` (комиссын эхлэл, жишээ нь 12/15) эсвэл өнөөдөр−2 хоногоос хойших илгээсэн мөр.
10. Бүх `SaveData` нь баримтжуулсан `IfError(SaveData(...);true,false)` хэлбэрээр шалгагдана (`IsError(SaveData)` үлдээгүй).

Экспорт аль хэдийн `IfError(PA_ExportInventoryCSV.Run(JSON(...)),…)` дотор — `JSON()` унавал flow дуудагдахгүй. Мөр/₮-ийн тулгалт, хэсэгчилсэн файлыг илгээхгүй байх → r5.2.

## Хязгаар
- `SaveData` бичилт дундаа тасрах үед файл юу болохыг Microsoft баримтжуулаагүй → T4/T4b-ээр шалгана.
- Windows-ийн `JSON()` босгыг Samsung-ийн хязгаар гэж үзэхгүй; хамгаалалт аль ч хязгаарт ажиллана.
- InventoryCount-д тавиур (bin) талбар байхгүй — комиссын тооллого тавиураар явбал 12/5-аас өмнө нэмнэ.
- Түүхийн засвар (10 → 5) нь шинэ SyncKey-тэй шинэ мөр үүсгэдэг (кодоор шалгасан) тул зөрчил биш; нэгдсэн тайлангийн "сүүлийнх нь хүчинтэй" дүрэм → r5.2.

## Урьдчилсан нөхцөл
InventoryCount-д index: `Created`, `Counter`, `CountKeyV27`, `Title`, `LocationCode`.
