# v10-1_5b r5 — Power Apps MVP-1: хадгалалт түүхийн хэмжээнээс хамаарахгүй

**Суурь:** `TME-v10-1_5b-r4.2-count-TEST.msapp` — 1,703 мөрийн туршилтад ашигласан Version 3 (эх код `../../v10-1_5b_r42count_studio/Src`). 15 property. Скрипт `../fix_r5.py` (TEST_1 дээр ч ажиллана).

**Яагаад яаралтай:** тусгаарласан туршилтаар Power Fx `JSON()` нэг дуудлагад **1,048,576 байт**-аас (энэ өгөгдөлд ~1,767 мөр) их бол алдаа өгдөг. Одоогийн хувилбар хадгалах бүрт бүх түүхийг нэг `JSON()`-оор хөрвүүлдэг тул түүх ~1,700 мөр давмагц **дахин нээсний дараах эхний хадгалалт унана**. r5 нь зөвхөн илгээгээгүй мөрийг (`C22P`), илгээсэн түүхээс хамгийн сүүлийн **1,000 мөрийг** (`C22H`, ~0.6 MB) бичнэ. Бүх бичилт payload-аа эхлээд бүрдүүлж шалгадаг (`IsError`, `[`…`]`); буруу бол хуучин файлыг **дарж бичихгүй**.
Studio-д: property бүр → formula bar Ctrl+A → Ctrl+V. Бүгдийг оруулсны дараа App Checker 0 алдаа.

## Юу өөрчлөгдсөн
| | Өмнө (TEST_1) | r5 |
|---|---|---|
| Хадгалах бүрт дискэнд | **Бүх** түүх (`C21`, илгээгдсэн мөр ч). Codex-ийн append нь JSON-ийг хурдасгасан ч файлын хэмжээ өссөөр | Зөвхөн **илгээгдээгүй** мөр (`C22P`, ихэвчлэн 0–30 мөр) |
| Илгээгдсэн түүх | Хадгалах бүрт | `C22H` (сүүлийн ≤1,000 мөр) — зөвхөн SharePoint-оос сэргээх үед, мөн дараалал хоосорсон үед **10 мин-д нэг удаа** (upload timer) |
| Санах ойн түүх | Бүх хугацаа | Илгээгдээгүй бүх мөр + **сүүлийн 3 хоногийн** (өнөөдөр+2) илгээгдсэн мөр (`varCountWindowDaysV22=2`) |
| SharePoint-оос сэргээх | Өөрийн бүх мөр (5,000 хязгаартай) | Өөрийн сүүлийн 3 хоногийн мөр |
| Хуучин `C21` | — | Анх нээхэд нэг удаа уншиж `C22P`+`C22H` бичнэ; хоёулаа амжилттай болсны **дараа л** `C21`-ийг устгана |

Илгээгдээгүй мөр хэзээ ч цонхоор хасагдахгүй. `C22H` уншиж чадахгүй бол хадгалалтыг хаахгүй (зөвхөн түүх дутуу харагдана).

## Хүлээгдэх үр дүн
- Хадгалалтын хурд **түүхийн мөрийн тооноос хамаарахгүй** (дискэнд бичих хэмжээ тогтмол). Хурдны мөрний "түүх N мөр" нь 3 хоногийн цонх болно.
- Апп нээгдэх: SharePoint-оос 3 хоногийн мөр л татна.
- Тооллого бүрт дахин тооцоологддог 40+ томьёо 3 хоногийн мөрөөр л ажиллана.

## Хязгаар (MVP)
- Төхөөрөмж дээрх **түүх, 8 сарын график, өөрийн тайлан** (ScrHistory, ScrSync, ScrReport1, ScrDashboard) сүүлийн 3 хоногийг л харуулна. Нэгдсэн тайлан (ScrCombined) SharePoint-оос уншдаг тул бүрэн хэвээр.
- Офлайн байхдаа аппыг дахин нээвэл илгээгдсэн мөрүүд `C22H` бичигдсэн хэмжээгээр (≤10 мин хоцрогдолтой) харагдана; сүлжээнд ормогц бүрэн болно. Өгөгдөл алдагдахгүй — SharePoint-д бий.
- 3-аас өөр хоног хэрэгтэй бол `App.OnStart` дахь `Set(varCountWindowDaysV22,2)`-г өөрчилнө.

## Урьдчилсан нөхцөл
SharePoint **InventoryCount** → List settings → Indexed columns: `Created`, `Counter` (сэргээх шүүлт), мөн `CountKeyV27`, `Title`, `LocationCode`.

## Тест (Samsung)
1. Хуучин түүхтэй хэрэглэгчээр (Од) r5-ийг нээх → өмнөх илгээгдээгүй мөрүүд хэвээр, "Локал · N" өмнөхтэй ижил. Сүлжээнд холбогдсоны дараа SharePoint-д давхардалгүй.
2. **1MB тест:** ~2,000 мөр түүхтэй хэрэглэгчээр (эсвэл туршилтын 1,703 мөрийн дараа) аппыг хааж нээгээд **эхний хадгалалт амжилттай** байна.
3. 20+20 хадгалалт → хурдны мөрний "түүх" ≤ 3 хоногийн мөр, P50/P95 TEST_1-ээс бага эсвэл тэнцүү.
4. Офлайн: 5 тооллого → аппыг бүрэн хааж нээх → 5 мөр "Локал · 5" → сүлжээ → бүгд нэг удаа илгээгдэнэ.
5. Аппыг 2 удаа хааж нээх → `C21` шилжүүлэлт давтагдахгүй (мөр давхардахгүй).
6. Офлайн нээлт → хадгалах товч ажиллана (диск аюулгүй уншигдсан).
