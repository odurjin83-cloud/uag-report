## Хурдны лог (4)
- Өмнө: 20 дахь хадгалалт бүрт `TotalMs` авсны **дараа** бүх raw түүхийг (`colPerfV1015`, мөр нэмэгдэх тусам томордог) дискэнд бичдэг байсан → тэр хугацаа хэмжилтэд ороогүй, мөн хэмжилт өөрөө аппыг удаашруулж байв. `PerfV1015_` файлыг хаана ч уншдаггүй байсан.
- Одоо: 20 хадгалалт тутам **нэг хураангуй мөр** `colPerfSumV1015` = {Block, At, HistoryRows, MedianMs, **P95Ms** (20-ийн 19 дэх), MaxMs, LocalMaxMs, PrevPersistMs}. Raw 20 мөрийг цэвэрлэнэ → raw хэзээ ч 20-оос хэтрэхгүй.
- Хураангуйг `PerfSumV1015_<ObjectId>` руу бичих хугацааг тусад нь хэмжиж, **дараагийн** мэдэгдэлд "өмнөх лог бичилт N мс" (алдаа бол "АЛДАА") гэж харуулна. Тиймээс 20 дахь хадгалалтын нэмэлт зардал нуугдахгүй.
- Restart-ын дараа эхний хураангуйн өмнө хуучин файлыг **түр collection**-д `LoadData`-аар уншина. **Амжилттай уншсан үед л** `varPerfSumLoadedV1015=true` болж, тухайн түлхүүрт бичнэ; энэ сессийн өмнөх хураангуйнуудыг хуучин логийн араас дугаарыг нь үргэлжлүүлж (#N+1…) нэгтгэнэ. Уншилт амжилтгүй бол **дискэнд огт бичихгүй** (хуучин лог дарагдахгүй), хураангуй санах ойд үлдэж, мэдэгдэлд "өмнөх лог бичилт ХИЙГДЭЭГҮЙ" гарна; дараагийн 20 дахь хадгалалтад дахин уншихыг оролдоно.
- Тест: 20 + 20 хадгалалт (аппыг хаалгүй) → 40 дэх мэдэгдэлд "өмнөх лог бичилт N мс" → аппыг хааж нээгээд 20 хадгалах → **#3**.
- `false` үед хадгалах товч `varPerfT0V1015`/`varPerfT1V1015`-ийг шинэчилсээр байгаа (2 `Set`, зардал нь мэдэгдэхүйц биш). Лог, диск, мэдэгдэл бүгд унтарна.
- 5,000 хадгалалт ≈ 250 хураангуй мөр — 1, 100, 500, 1,000, 3,000, 5,000 дахь мөрийн P50/P95-ийг `HistoryRows`-оор харьцуулна.
- `TotalMs` = товч дарснаас томьёо дуусах хүртэл. Дэлгэц дахин зурагдах хугацаа орохгүй — бодит "дараагийн код оруулахад бэлэн" хугацааг дэлгэцийн бичлэгээр тулгана.

⚠️ Non-blocking OnStart: апп нээгдсэний дараах эхний хэдэн секундэд хадгалалт хийвэл унтраалга хараахан асаагүй байж болно — тэр хадгалалтууд хэмжилтэд орохгүй (аюулгүй).
